# 3D_Task

Backend системы управления проектами и задачами для малых студий, занимающихся разработкой графики: роли в проектах, иерархические задачи с циклом проверки, журнал событий, уведомления и версионируемое файловое хранилище с возобновляемой загрузкой больших файлов.

## Зачем это нужно

Студии, которые делают 3D-графику и анимацию, работают с тяжёлыми файлами (модели, текстуры, рендеры) и многоступенчатой проверкой результата. Универсальные трекеры не имеют предметно-ориентированного функционала, а специализированные системы слишком тяжеловесны для малых студий и зачастую требуют содержания отдельных специалистов. Этот проект закрывает именно такой сценарий.

## Возможности

- **Проекты и роли.** Создание проектов, приглашение участников, роли внутри проекта: `CREATOR`, `TASK_CREATOR`, `USER`.
- **Иерархические задачи.** Подзадачи, несколько исполнителей и проверяющих, комментарии, дедлайны.
- **Цикл проверки.** Исполнитель сдаёт задачу на проверку, проверяющий принимает или возвращает на доработку.
- **Журнал событий.** Смена статуса, назначение и снятие исполнителей и проверяющих, смена родителя и дедлайна, редактирование.
- **Уведомления.** Уведомления по проекту с отметкой «прочитано».
- **Файлы.** Загрузка больших файлов напрямую в S3-совместимое хранилище через multipart upload и presigned URL, с возможностью отмены и докачки прерванной загрузки. Версионирование файлов, аннотации к файлам.
- **Статистика.** Сводка по задачам проекта и по продуктивности участников.
- **Аутентификация.** JWT (access и refresh токены), пароли хешируются BCrypt.

## Архитектура


Приложение разделено на слои: контроллеры принимают запросы и отдают DTO, бизнес-логика и проверка прав находятся в сервисах, доступ к данным через репозитории Spring Data JPA. Файлы не проходят через сервер приложения: клиент получает presigned URL и загружает части напрямую в хранилище.

### Роли

Глобальные роли пользователя: `USER`, `ADMIN`. Роли внутри проекта: `CREATOR`, `TASK_CREATOR`, `USER`.

| Действие | Кто может |
|---|---|
| Редактировать проект | `CREATOR` |
| Создавать задачи | `CREATOR`, `TASK_CREATOR` |
| Отправить задачу на проверку | исполнитель задачи |
| Выставить статус по итогам проверки | проверяющий задачи или `CREATOR` проекта |

### Аутентификация

1. `POST /auth/register` и `POST /auth/login`: в ответ приходят access- и refresh-токены.
2. Защищённые запросы идут с заголовком `Authorization: Bearer <access_token>`.
3. Когда access-токен истекает, новая пара токенов выдаётся по refresh-токену через `/auth/refresh`.


## Старт

Требования: Docker и Docker Compose.

docker compose up --build

После запуска:

- API: `http://localhost:8080`
- Консоль MinIO: `http://localhost:9001`

Запуск без Docker: нужны JDK 25, запущенные PostgreSQL и MinIO, переменные окружения из таблицы ниже и команда `./mvnw spring-boot:run`.

## Конфигурация

| Переменная | Назначение |
|---|---|
| `JWT_SECRET` | ключ подписи JWT |
| `DB_URL` | JDBC URL PostgreSQL |
| `DB_USER`, `DB_PASSWORD` | учётные данные БД |
| `S3_ENDPOINT` | адрес MinIO / S3 |
| `S3_ACCESS_KEY`, `S3_SECRET_KEY` | ключи доступа к хранилищу |
| `S3_REGION` | регион |
| `S3_BUCKET` | имя бакета для файлов |

## Структура проекта

```
src/main/java/com/example/_d_task/
├── controllers/     REST-контроллеры
├── services/        бизнес-логика и проверка прав

├── models/          JPA-сущности
├── dto/             объекты передачи данных

└── s3/              конфигурация клиента S3
```
